# 🐦‍⬛ 까마귀봇 v4.5

## v4.5 종합게임 로테이션 운영

- 관리자: `/종합게임 모집 게임:배틀그라운드 인원:3 로테이션판수:2`
- **로테이션판수는 안내 문구 전용**입니다. 해당 팀이 2판을 플레이한 뒤 관리자가 [다음 로테이션]을 한 번 누르면 됩니다. 봇은 각 게임 판수를 추적하거나 한 판마다 버튼을 요구하지 않습니다.
- **[명단 확정]**: 신청 순서 기준으로 정원 내 인원을 1회차 팀으로 확정합니다.
- **[다음 로테이션]** 또는 `/종합게임 다음로테이션`: 확정된 기존 팀을 대기열 맨 뒤로 보내고 기존 대기자 우선으로 다음 팀을 바로 확정합니다. 팀이 바뀐 횟수만 표시합니다.
- **확정 이후에도 신규 신청 가능**: 새 신청은 현 확정팀을 밀어내지 않고 대기열로 들어갑니다. 확정된 팀원은 취소·정보 수정을 할 수 없지만, 대기자는 수정·취소할 수 있습니다.
- 대기자가 없으면 [다음 로테이션] 버튼을 비활성화합니다. 기존 참가자를 다른 사람으로 교체하려면 새로운 대기 신청이 필요합니다.
- 관리자가 [확정 취소]를 누르면 모집 상태로 돌아오며, 현재 대기열 순서를 유지합니다. [모집 종료]는 최종적으로 모집을 닫고 기록을 보관합니다.
- 기존 v4.4.1 진행 중 모집판은 그대로 호환되며, 과거에 지정하지 않은 로테이션판수는 **안내용 1판**으로 표시합니다. 새 설정은 **새로운 모집**부터 적용됩니다.

# 🐦‍⬛ 까마귀봇 v4.3

v3의 롤 5:5 내전 기능을 유지하면서, **솔랭 유료 듀오(선착순)**와 **자랭 무료 시참(독립 판수 로테이션)** 모집판을 제공합니다. v4.2부터 세 모드 모두 **하나의 롤 프로필을 필수로 공유**합니다.

## v4.3 내 정보 수정 버튼

- 내전·솔랭 듀오·자랭 모집판 모두 **[✏️ 내 정보 수정]** 버튼을 제공합니다.
- 기존 롤 프로필이 있으면 기존 `/내전수정`과 동일한 수정 모달이 열리고, 없으면 최초 프로필 등록 모달이 열립니다.
- **닉네임#태그, 현재 티어, 최고 티어, 선호 라인**을 수정하면 세 모드가 공유하는 동일한 SQLite 프로필에 저장됩니다.
- 현재 모집판에 참가 중이라면 저장 후 명단에 최신 롤 계정 정보가 반영됩니다. **내전 경기 중 화면에는 최신 프로필을 표시하지만 시작 당시 확정 명단 기록은 보존**합니다.
- 모집이 종료된 게시판의 편집 버튼은 비활성화됩니다. 필요하면 `/내전수정`은 계속 사용할 수 있습니다.
- 대기열 순서, 승인 여부, 참여 판수는 프로필 수정으로 변경되지 않습니다.

## v4.2 공통 롤 프로필 의무 등록

- **내전·솔랭·자랭 모두** 최초 참가 시 프로필이 없으면 기존 `/내전등록`과 동일한 등록 모달이 열립니다.
- 입력: **롤 아이디#태그, 현재 티어, 최고 티어, 선호 라인** (기존 등록 형식 및 SQLite 데이터 재사용)
- 모달 저장을 완료하면 **원래 눌렀던 참가 버튼의 모드·획득 경로에 따라 자동 참가**합니다. 후원/룰렛 신청은 여전히 **관리자 확인 대기**로 들어갑니다.
- 이미 등록된 사용자는 모달 없이 버튼 한 번으로 참가합니다.
- 모달 등록 도중 해당 모집이 종료되거나 교체되었다면 **프로필만 저장**하고 다른 모집에 자동 입장시키지 않습니다.
- **과거 버전의 미등록 대기자**는 우선순위를 유지한 채 등록 가능하며, 선발 예정자가 프로필 미등록 상태면 게임 시작을 막고 `/내전등록`을 안내합니다.
- 모집판에서 **디스코드 @사용자 / 롤 아이디#태그**가 표시됩니다.
- 내전 판수, 자랭 판수, 솔랭 유료 듀오권 승인 및 선착순 로직은 변경하지 않았습니다.

## v4 솔랭 듀오 (스트리머 + 시청자 1명)

- 관리자: `/솔랭 모집`으로 독립 모집판 생성
- 시청자: **[5,000원 듀오 신청]** 또는 **[룰렛 듀오권 신청]** 클릭
- 신청은 먼저 **확인 대기(미승인)** 상태로 들어감
- 관리자가 후원/룰렛 당첨 또는 사용권 보유 사실을 **외부에서 확인**한 뒤 [승인 관리] 또는 `/솔랭 승인 유저:@사용자`로 승인
- 관리자가 [듀오 시작] 또는 `/솔랭 시작` → 승인된 신청자 중 **선착순 1명** 선발
- `/솔랭 게임종료` 또는 [게임 종료] → 이번 듀오 참가자는 대기열에서 자동 제외, 다른 참가자는 유지
- `/솔랭 현황` / `/솔랭 제외` / `/솔랭 종료` 지원
- **중요**: 봇은 치지직 후원, 뚜봇 룰렛/사용권과 연동되지 않음. 신청 버튼만으로 결제나 듀오권을 증명할 수 없으며, 관리자 승인과 실제 사용권 차감·정산은 별도 운영 필요
- 미승인자는 자동 선발되지 않음. 승인된 참가자끼리는 신청 시각이 아니라 **신청 순서(FIFO)** 기준

## v4 자랭 시참 (스트리머 + 시청자 4명)

- 관리자: `/자랭 모집`으로 독립 모집판 생성
- 시청자: **[무료 시참 신청]**, [신청 취소], [내 대기 현황]
- `/자랭 시작` 또는 [팀 확정] → **참여 판수 적음 → 직전 판 미참여 → 오래 기다림 → 신청 순서** 순으로 시청자 4명을 확정 (4명 미만이면 시작 불가)
- 판수는 **이번 자랭 모집에만** 저장. 기존 내전 판수와 섞이지 않으며 솔랭의 선착순에도 영향 없음
- 자랭 게임 **시작 시 확정 참가자의 판수가 1 증가**하고, 다음 판 예상 명단·대기열·내 상태에 참여 판수가 표시됨
- 취소·관리자 제외·게임 종료 후에도 **해당 자랭 모집 기록은 유지**되어 다시 신청하면 기존 판수로 정렬 (새 모집 생성 시 0판부터)
- 관리자: [판수 변경] 버튼 또는 `/자랭 판수변경 유저:@사용자 증감:1`으로 현재 대기 중인 참가자의 판수를 조정할 수 있음
- 기존 v4에서 진행 중인 자랭 모집판도 저장된 `rounds` 기록으로 누락 판수를 최초 접근 시 복원
- `/자랭 게임종료` 또는 [게임 종료] → 확정된 4명 자동 제외, 기다리던 나머지는 그대로
- `/자랭 현황` / `/자랭 제외` / `/자랭 종료` 지원

## 공통 동작과 운영

- 기존 `/내전` 명령어와 프로필 등록(`/내전등록`, `/내전수정`, `/내전정보`)은 변경하지 않음
- 내전·솔랭·자랭은 각각 **별도 모집판·대기열·게임 진행 상태** 사용. 동시에 모집 가능
- 솔랭/자랭 참가 시 **롤 프로필 등록 필수**. 내전에서 등록한 프로필을 그대로 사용하고, 미등록자에게는 등록 모달 표시
- 모집 메시지는 **판마다 새로 작성하지 않고 기존 모집판을 수정**
- 관리자 권한: 서버 관리 또는 메시지 관리 권한
- 자랭은 내전과 **같은 로테이션 규칙, 다른 판수 데이터**를 사용하고, 솔랭은 선착순을 유지
- 진행 중인 게임은 종료 처리 후 모집판 종료 가능
- 기존 `data/state.json`을 유지하고 `modeQueues` / `modeQueueHistory` 필드를 추가 저장. 이전 v3 데이터는 그대로 읽힘

- 기존 참여 기록은 현행 `data/state.json`, 신규 프로필은 `data/profiles.sqlite`에 저장

## 명령어

- `/내전 모집` — 모집판 생성 (관리자)
- `/내전 시작` / `/내전 다음판` — 9명 선발 및 게임 진행 (관리자)
- `/내전 게임종료` — 종료 후 참가자 대기열 자동 제외 (관리자)
- `/내전 제외` / `/내전 판수변경` / `/내전 테스트모드` — 기존 관리자 기능
- `/내전 현황` — 현재 진행 현황
- `/내전등록` — 최초 프로필 사전 등록
- `/내전수정` — 기존 프로필 수정
- `/내전정보` — 본인 프로필 보기

## 설치 및 실행

**Node.js 24 권장** (Node.js 22.13 이상에서 내장 SQLite 이용 가능). 별도 SQLite 패키지는 설치하지 않습니다.

```bash
npm install
npm test
npm start
```

`npm start` 시 DISCORD_CLIENT_ID와 DISCORD_GUILD_ID가 있으면 새 슬래시 명령어를 자동으로 갱신합니다. 환경변수가 없거나 등록에 실패한 경우에는 `npm run register`로 수동 등록해야 합니다.

`.env`에는 기존대로 `DISCORD_TOKEN`, `DISCORD_CLIENT_ID`, `DISCORD_GUILD_ID`를 설정합니다.

## 게임 시작 처리 주의

- 오늘내전 사이트 API와 직접 연동하지 않습니다.
- 스트리머가 오늘내전 신규 참가자 등록/팀 매칭을 마친 뒤 봇의 **게임 시작**을 누르면, 그때 선발된 9명을 오늘내전 '등록됨'으로 기록합니다.
- 게임 시작 전 롤 프로필이 없는 참가자가 있으면 **일반·테스트 모드 모두** 게임 시작을 막고 `/내전등록`을 안내합니다. 테스트 모드는 9명 인원 조건만 완화합니다.
- 확정 참가자 명단은 **✅ 기존 / 🆕 신규** 두 상태만 표시하며 별도 미등록 분류는 없습니다.
- 게임이 시작하면 기존 로테이션 로직에서 **판수를 한 번만 증가**시킵니다.
- **게임 시작·종료 시 별도 명단 글을 작성하지 않고 기존 모집판만 수정**합니다. 최근 게임 중 명단은 시작 당시 스냅샷을 표시하고 경기 기록은 상태 파일에 유지합니다.
- `게임 종료`를 누르면 현재 9명은 대기열에서 제외되며 다음 판 참가에는 재신청이 필요합니다.

## 데이터 백업

`data/state.json` 과 `data/profiles.sqlite`는 모두 중요합니다. GitHub에 올리지 말고 서버 바깥으로 각각 백업하세요. **외부 자동 백업은 아직 구현하지 않았습니다.**

```bash
cp data/state.json state-backup.json
cp data/profiles.sqlite profiles-backup.sqlite
```

백업은 가능하면 봇을 중지한 상태에서 수행하거나 SQLite의 안전한 백업 API를 사용해야 합니다.

## 배포 전 확인

1. 현재 운영용 `main`과 `data/state.json` 별도 백업
2. `feature/v3-profile-registration` 작업 브랜치에 파일 추가·교체
3. 현재 `package-lock.json`을 보존한 채 `npm install`로 버전 메타데이터 갱신
4. `npm run register`로 새 명령어 등록
5. `npm test` 실행 후 실제 디스코드 테스트 서버에서 등록/시작/종료 점검
6. 확인 후 운영 서버 배포

Discord 실사용 테스트는 Bot-Hosting 접근과 실제 디스코드 애플리케이션 권한이 필요합니다.

- **확정 참가자 표시 순서:** 🆕 신규 참가자 먼저, ✅ 기존 참가자 다음. 같은 그룹에서는 기존 선발 순서를 유지하며, 대기열 우선순위·실제 선발·판수 기록은 변경하지 않습니다.
